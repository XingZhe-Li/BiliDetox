# 时段锁

入口：哔哩哔哩 → 设置 → BiliDetox 设置。时段锁与发誓锁各有独立的二级页面；页内返回按钮或系统返回键可回到主设置。

## 使用规则

- 初始状态为禁用，预置夜间 **23:00–次日 06:00**。
- 可以添加、编辑或删除多个每日重复的时段，也可以恢复夜间预设。结束时间早于开始时间表示跨午夜。
- 开始时间包含在锁定范围内，结束时间不包含。例如 23:00 开始锁定，06:00 恢复使用。
- 重叠、相邻的时段连续生效。不能删除最后一个时段，不能设置开始与结束相同，也不能让多个时段合起来覆盖全天。
- **普通锁**：启用后，当天不能关闭或修改时段；最早可在次日的可用时段操作。设置按钮会说明当前限制。
- **发誓锁定**：在独立的「发誓锁」页面选择一个未来的终止日期和时间，再确认锁定。它可以独立启用，不要求开启时段锁，也不会自动开启或改变时段锁。若需要限制观看时间，应先配置好时段锁再发誓。
- 誓约到期前，**BiliDetox 的全部可编辑选项都被冻结**：包括主设置页的所有开关、时段锁的启用状态、时段和誓约终止时间。即使处于可用时段，也不能修改；仍可浏览设置及返回主设置，可用时段仍能正常使用 B 站。
- 主设置页会显示誓约终止时间，所有开关置灰并保留当前状态；誓约到期后自动恢复各项原有编辑规则，无需重开设置页。普通时段锁不冻结其他功能开关。
- 页面每秒自动检查配置、誓约和时段边界，不提供手动刷新按钮。前台播放中进入禁用时段，也会自动显示拦截页并请求暂停播放，无需退出重开。
- 誓约到期不会自动关闭每日时段锁。关闭或修改仍须满足「启用次日以后且处于可用时段」。到期落在禁用时段时，需要继续等到首次可用时间。

锁定页面显示当前限制、全部时段、首次可用的日期时间，以及生效中的誓约终止时间。返回键和退出按钮将应用移到后台，不解除锁。到达可用时段会自动移除拦截，不需要重启应用。

## 实现范围

时段和日期使用设备当前时区，誓约终止时间保存为绝对时间戳。普通锁的次日从启用时的本地日期计算，使用日历推进，避免把夏令时的次日当作固定 24 小时。

`TimeLockHook` 在宿主各进程的 `Instrumentation` 生命周期入口检查 Activity，覆盖普通启动、深链、页面切换、后台返回。页面可见时每秒检查一次，也会在使用中进入限制时段时显示不透明拦截页。被锁时禁止进入系统画中画，已在系统画中画中的页面会关闭。模块跟踪宿主自身的媒体会话，在限制时段内请求暂停，防止视频加载完成后在拦截页后面继续播放；后台音频播放时也继续检查时段边界。拦截页另通过音频焦点通知播放器停止播放。媒体暂停最终由宿主的媒体会话回调处理。

配置沿用宿主数据目录的 `files/bilidetox.json`，增加独立的 `timeLock` 对象。为兼容旧配置，誓约终止时间仍存储于 `timeLock.pledgeUntil`；生效判断独立于 `enabled`，时段锁关闭时仍冻结设置。旧配置缺少该字段时保持禁用。所有设置修改在保存前经过 `ConfigEditPolicy` 的整份配置校验，防止通过旧页面、其他开关入口或同时清除誓约的批量修改绕过。写入先生成完整临时文件，再在同目录原子替换，避免其他进程读取半份 JSON。

这是应用内的自律限制，依赖模块正常加载及设备系统时间；修改系统时间、停用模块或清除宿主数据不属于防护范围。

## 规则测试

无需设备或 Android 运行时，安装 Kotlin 命令行编译器后，在仓库根目录运行：

```sh
kotlinc app/src/main/java/com/github/xingzheli/bilidetox/TimeLockPolicy.kt tools/tests/TimeLockPolicyTest.kt -include-runtime -d tools/build/time-lock-tests.jar
java -jar tools/build/time-lock-tests.jar
kotlinc app/src/main/java/com/github/xingzheli/bilidetox/HomeConfig.kt app/src/main/java/com/github/xingzheli/bilidetox/TimeLockPolicy.kt app/src/main/java/com/github/xingzheli/bilidetox/ConfigData.kt tools/tests/ConfigEditPolicyTest.kt -include-runtime -d tools/build/config-edit-tests.jar
java -jar tools/build/config-edit-tests.jar
```

测试覆盖关闭状态、夜间和同日时段、精确边界、多时段及相邻重叠、无效与全天时段、次日关闭规则、誓约追加及禁止修改、到期边界、到期后继续每日锁定，以及夏令时。全局编辑策略另覆盖首页管理和其他功能的全部开关的两个切换方向、誓约到期、普通锁的限制范围，以及批量修改绕过。

真机回归时应备份原配置。注入短时测试配置可通过 debuggable 宿主和 `adb shell run-as tv.danmaku.bili` 完成；发布包不添加此标记。该测试机的直播预览会在 debuggable 模式的 CheckJNI 校验中因原生日志的无效 Modified UTF-8 触发中止，并可能在退出直播页时发生 ANR，因此涉及直播及页面切换的验收应使用普通包。不要为验证长期锁定而清除用户数据或修改系统日期。
